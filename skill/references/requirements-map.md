## B01 的八个语义子项

| 子项 | 必须逐条确认的内容 |
|---|---|
| B01.1 Goal | 2–4句说明给定什么、产出什么、优化何指标及方向；一行定义合法提交；无方法提示。 |
| B01.2 Task Setting | sandbox/GPU作业方式、Starter与正式Baseline关系、公开Dev迭代、Hidden隔离；已有公开Dev基线值按真实材料填写。 |
| B01.3 Objective and Metrics | 主指标精确公式、聚合、原始min/max方向、非计分诊断、质量门；连续单调不裁剪，不在B/R处分段；多目标单位/权重/缺失值处理明确。 |
| B01.4 Allowed Scope | 准确可改/新增路径、实际可用平台接口、可读数据位置与公开评分命令；不存在的工具不写成可用。 |
| B01.5 Hard Boundaries | 可执行gate、保护面可信恢复、大小/时间/资源/并发GPU限制、禁Hidden/篡改/伪造；候选应源自官方scaffold及自己的真实运行。 |
| B01.6 Submission Instructions | 本题真实文件清单、必选/可选字段或固定文件接口、写入与解析命令；不信候选自报分。无提交JSON则不虚构JSON。 |
| B01.7 Workflow & Iteration | anytime语义；implement→公开launch/observe或等价评分→保留/回退→更新当前best；最近有效提交受评；单轮墙钟预算明确。 |
| B01.8 Completion Criteria | 合法接口/Schema、自己的成功运行、gate通过、有限分、必要产物齐、保护面未改、Hidden未访问。 |

八标题存在只证明结构。语义子项缺失不能通过；官方 QA 接受同义章节时，记录真实八部分映射，不因标题拼写制造冲突。

## 当前采用口径与冲突处理

1. 用户明确阶段/禁止事项 > 工作区现行规则 > 当前正式格式/官方 QA > 教程布局示例。冲突记录两边出处、适用阶段与采用理由；不能偷偷弱化必达项。
2. 当前三目录是最终目标；pre_run只冻结可运行题目及已有B/R/专家骨架。轨迹、唯一best_method和真实长程统计列post_run待生成，不生成假轮次、不用Reference替代。教程§4的长跑后完整性不提前套用。
3. 选唯一Docker profile。`teaching-task-root-v1`以harbor_task为context，`harbor-environment-v1`以environment为Agent context；独立Verifier以tests为context。旧task-root必须有实际适配且不能把私有tests带入Agent。源码根solution可选Oracle；运行时候选路径必达，PCA144/官方H03优先澄清原目录示意。
4. `schema_version=1.3`、`autoresearch-comparison-summary.v2`是示例，不是通用平台保证。真实目标Schema/版本与映射优先；不能仅由verifier.environment小节推定separate实际生效。
5. 本任务要求交付hidden_assets为空。官方QA允许等价目录与生成/注入方式，不为名字造内容；私有预置例外不用于绕过本任务空目录要求。必须有可定位生成/安全注入及调用证据，空目录本身不证明Hidden准备完成。
6. Starter可以是Scaffold，正式B必须有独立可运行合理Baseline与锚点映射。不能因Starter不给method否定G02，也不能把Scaffold分数冒充正式B。
7. 3–5σ按现行官方QA可接受并建议复核；本阶段禁止增加训练，记录复核提示/已有授权缺口。只读复算检查已冻结统计，不覆盖原件；若发现真实反证，暂停准入，不改U或挑seed。
8. NOP当前为官方QA v0.3.2必交，必须是当前题包版本；缺材料是本阶段真实缺口。H05按已有配置适用，H06不可因旧“有材料才查”省略。NOP仅覆盖所运行分支，不能代替P5模型/完整PublicDev链路。
9. 专家侧只需实际运行中的健康观察；连续12h soak不是pre_run或专家提交闸门。两条各10h有效研究与每阶段≤12h墙钟硬截止属于后续运行合同，不能填入尚未执行的结果。
10. 官方QA额外材料通常给精简建议；本套件冻结输出须严格白名单。原归档中的额外材料不自动判原成品科研不合格；新冻结副本的未声明成员是结构不一致，记录精简动作，绝不删除原件。

官方审核的 G01–G03、B01–B08、QA01–QA21、H01–H06 使用原编号、原结论。套件层ID只引用其结论与版本，不重实现官方算法。pre_run适用性覆盖写在单独台账，不涂改官方pre_submit报告来获得“全通过”。
